## 一、先讲结论：这门课到底在训练什么？

这门课的核心不是“背很多算法名字”，而是训练你形成一种**算法化思维**：

`问题建模 -> 识别结构 -> 选择范式 -> 证明正确 -> 分析复杂度 -> 落成答案`

结合你的本地题库和 MIT / Berkeley / Stanford 的官方课程资料，可以把这门课理解成：

- **前半段**：学会衡量算法好坏
- **中间段**：学会识别一个问题属于哪类设计范式
- **后半段**：学会说明为什么这个算法对、为什么它快、为什么有些问题根本很难

所以你真正要建立的不是“知识点清单”，而是一个**五层认知框架**。

---

## 二、五层认知框架

```text
第 1 层：目标层 —— 这道题到底要求我求什么？
第 2 层：结构层 —— 这个问题内部有什么结构？
第 3 层：范式层 —— 我该用哪种算法设计思想？
第 4 层：证明层 —— 我怎么说明它是对的？
第 5 层：代价层 —— 时间 / 空间复杂度是多少？
```

你做题时，脑子里应该始终按这五层走，而不是一上来就写代码。

---

## 三、第 1 层：目标层

先问自己：

这题让我做的到底是什么？

常见目标只有几类：

1. **判定**：是否存在？是否可行？
2. **搜索**：找到一个满足条件的解
3. **优化**：最大 / 最小某个量
4. **计数**：有多少种方案
5. **构造**：把最优解本身写出来

### 这一层的意义

目标不同，算法范式会变：

- 只要“是否存在”，可能 DFS / BFS / 回溯就够了
- 要“全局最优”，就更可能走 DP / 贪心 / 分支限界
- 要“构造答案”，就要多考虑路径恢复、parent 指针、决策记录

---

## 四、第 2 层：结构层

这是整门课最关键的一层。

不是看到“背包”就想 DP，而是先看**结构**。

### 你要识别的 6 个核心结构

#### 1. 规模缩小且可合并
典型信号：
- 能拆成若干小问题
- 小问题和原问题同型
- 小问题解能合并

这通常指向：**分治**

#### 2. 最优子结构
典型信号：
- 原问题最优解由子问题最优解组成

这会出现在：
- 动态规划
- 贪心

#### 3. 重叠子问题
典型信号：
- 相同子问题会反复出现

这通常强烈指向：**动态规划**

#### 4. 贪心选择性质
典型信号：
- 每一步局部最优不会破坏最终全局最优

这通常指向：**贪心**

#### 5. 解空间树
典型信号：
- 方案是一层层试出来的
- 不合法就退回
- 要系统搜索所有可能

这通常指向：
- 回溯
- 分支限界

#### 6. 难问题边界
典型信号：
- 问题看起来需要穷举
- 很难找到多项式时间精确算法
- 题目开始讨论 P / NP / NP 完全

这通常进入：**复杂性理论 / NP 完全 / 随机算法**

---

## 五、第 3 层：范式层

把结构识别出来后，再选范式。

### 1. 分治 = “拆开做，再合起来”

关键词：
- 二分搜索
- 归并排序
- 快速排序
- 棋盘覆盖
- 循环赛日程表
- Strassen

适用判断：
- 子问题同型
- 规模缩小
- 相互独立或基本独立
- 结果可合并

你的脑内一句话：

> 这题能不能拆成几个更小但同类的问题，然后再把答案拼回来？

### 2. 动态规划 = “把重复算过的最优子问题存下来”

关键词：
- 0-1 背包
- LCS
- 编辑距离
- 矩阵连乘
- 最优三角剖分

适用判断：
- 最优子结构
- 重叠子问题

你的脑内一句话：

> 这题是不是在很多地方重复问“前 i 个元素 / 前缀 / 子区间”的最优答案？

### 3. 贪心 = “每一步看起来最对，就一路做下去”

关键词：
- 哈夫曼编码
- 最优装载
- 最小生成树
- Dijkstra（在非负权场景）

适用判断：
- 贪心选择性质成立
- 能证明局部最优通向全局最优

你的脑内一句话：

> 我能不能只做当前最优选择，而不必回头修正？

### 4. 回溯 = “试、错、退”

关键词：
- N 皇后
- 图着色
- TSP
- 子集 / 排列搜索

适用判断：
- 需要搜索解空间
- 可以边搜索边判非法
- 可以用约束剪枝

你的脑内一句话：

> 这题是不是必须枚举，但我可以尽早发现无效分支并砍掉？

### 5. 分支限界 = “带估价的搜索”

关键词：
- 最大团
- TSP
- 0-1 背包

适用判断：
- 不只是找可行解，而是找最优解
- 搜索时可以用上界 / 下界估计某分支有没有希望

你的脑内一句话：

> 这题要找最优解，那我能不能用界函数提前判死某些分支？

### 6. 随机算法 / NP 理论 = “知道边界在哪”

关键词：
- 蒙特卡罗
- 拉斯维加斯
- 舍伍德
- P、NP、NP 完全

你的脑内一句话：

> 这题如果精确求解太难，我至少要知道它难在哪、近似/随机化有没有帮助。

## 六、第 4 层：证明层

这是考试和刷题最大的区别。

刷题常常只要“做出来”，但课程考试更强调：

- 为什么对？
- 为什么能这样选？
- 为什么不会漏？
- 为什么不会错？

### 各范式对应的证明模板

#### 分治
- 通常用**归纳法**
- 证明递归基正确
- 假设子问题正确
- 证明合并后原问题正确

#### 动态规划
- 重点证明**状态定义对**、**转移方程对**
- 常见证明路线：
  - 定义 OPT
  - 分类讨论最后一步 / 最后一个决策
  - 得出 recurrence

#### 贪心
- 最难的不是写算法，是**证明最优**
- 常见两类证明：
  - greedy stays ahead
  - exchange argument

#### 回溯
- 重点证明：
  - 搜索空间定义完整
  - 剪枝不丢解
  - DFS 能遍历全部候选可行路径

#### 分支限界
- 重点证明：
  - 界函数是合法的
  - 被剪掉的分支不可能优于当前最优

## 七、第 5 层：代价层

复杂度不是附属品，而是这门课的“度量语言”。

### 你要形成的复杂度直觉

#### 1. 循环型
- 一层 `for`：常见 `O(n)`
- 两层嵌套：常见 `O(n^2)`

#### 2. 对半缩小
- 二分搜索：`O(logn)`
- 递归深度往往 `O(logn)`

#### 3. 每层 O(n)，一共 logn 层
- 归并排序：`O(nlogn)`

#### 4. 搜索树爆炸
- 回溯 / 穷举常见指数级
- 例如 `O(2^n)`、`O(n!)`

#### 5. DP 的代价 = 状态数 × 单状态转移代价

这句一定要形成肌肉记忆。

## 八、把这门课压缩成一个“决策流程图”

做题时按这个顺序想：

```text
1. 这题是判定、搜索、优化、计数，还是构造？
2. 是否能拆成更小同类问题并合并？ -> 分治
3. 是否有最优子结构 + 重叠子问题？ -> 动态规划
4. 是否存在局部最优可直接推进？ -> 贪心
5. 是否必须系统枚举解空间？ -> 回溯 / 分支限界
6. 是找任意可行解，还是找最优解？
   - 可行解搜索 -> 回溯
   - 最优解搜索 + 界函数 -> 分支限界
7. 最后写出正确性依据和复杂度
```

这就是你以后做题的“脑内导航”。

## 九、结合你的题库，当前最适合你的学习姿势

你的本地知识库统计显示：

- 高频不是“图算法细节刷穿”
- 而是“算法设计思想 + 正确性 + 复杂度 + 典型题型”

所以最适合你的认知顺序不是：

> 一个章节一个章节死背

而是：

> 先建立统一框架，再把每个算法放回框架里定位

我建议你把复习顺序固定成：

1. **先背框架**：五层认知框架
2. **再分范式复习**：分治 / DP / 贪心 / 回溯 / 分支限界
3. **每种范式只抓三件事**：
   - 什么时候用
   - 怎么证明
   - 复杂度大概什么级别
4. **最后才回到题目**：把题目当成“识别范式”的训练样本

## 十、你接下来复习时要反复问自己的 8 个问题

1. 这题目标是什么？
2. 这是优化题还是可行性题？
3. 有没有最优子结构？
4. 有没有重叠子问题？
5. 局部最优会不会害死全局最优？
6. 这是子集树还是排列树？
7. 我该证明什么：可行性、最优性还是复杂度？
8. 我的答案最终能不能用一句话解释“为什么它是这个范式”？

如果你能把这 8 个问题练成下意识，你这门课的认知框架就算真正立住了。

## 十一、最短总纲

如果把这门课压成一句话：

> **算法设计与分析 = 用结构识别来选择算法范式，用证明与复杂度来完成答案。**

如果压成两句话：

> **先看结构，再选范式；先证明为什么对，再分析为什么快。**
