   02 / 简单科普：大多数 AI 的"记忆"是什么样的

   在拆 OpenHuman 之前，我们先简单过一下"普通" Agent 的记忆系统长什么样。

   大多数产品的做法是：

   Agent 的系统提示词里有一句话“当你觉得这事对定义用户和帮你未来更好的做事有用，把它写下来，存到 XXX.md文档里。”

   有些文档，是默认强行插入 Agent 上下文的，比如 USER.md、SOUL.md这种；

   有些文档，会在用户明确提到的时候 Agent 去阅读，比如memory/2026-05-06.md这种日记型的。

   还有些产品会在用户静默时(比如凌晨 4 点)激活一个 Agent 读取当日会话，从里面提取有用的信息，存到某个文档或者SQlite数据库里。

   等到用户某天提出涉及记忆相关需求时，在文档或者数据库搜索后使用。

   这些“记忆”方式整体上没啥毛病，但有两点点小细节：

   
    只能是边用边构建，你过往的信息，Agent 没法知道

    Agent 友好，但人不方便看+编辑

   

   OpenHuman 核心就是在解决这俩问题，并且方式有点优雅。

   03 / 记忆树：OpenHuman 的核心设计

   OpenHuman 的记忆系统叫 Memory Tree，翻译过来就是记忆树。

   这不是一个修辞手法，它真的是树形结构，而且是三层树。

   三层树，三种作用域

   尝试思考一下你的大脑是怎么处理信息的：

   
    感官记忆：看到、听到、读到的一切，先存着

    工作记忆：把感官记忆整理成"现在在处理什么"

    长期记忆：再压缩、抽象化，变成"我知道什么"

   

   OpenHuman 的三层树，几乎就是这个结构的工程化版本：

   第一层：源树（Source Tree） —— 每个数据来源一棵

   大家在宣传的 OpenHuman 可以接入 118 个信源，就是用来干这个的：

   你接了一个 Gmail，就有一棵 Gmail 源树。接了一个 Slack 频道，就有一棵 Slack 源树。

   每棵树独立管理自己的原始数据。

   第二层：主题树（Topic Tree） —— 按人物/项目/话题聚合

   当某个实体（比如你的同事"张三"）在多个来源中反复出现，系统会自动为"张三"创建一棵主题树，把他相关的所有信息——邮件、聊天、文档——都聚合到一起。

   第三层：全局树（Global Tree） —— 跨来源的每日/周/月/年回顾

   每天凌晨，系统自动跑一次，把所有源树当天的"精华"汇总成一份每日摘要。

   7 个每日摘要再压缩成一个每周摘要，4 个每周摘要压缩成每月……以此类推。

   
    
   
   
    💡 产品洞察：

    大多数 AI 记忆是"平"的——所有信息都在一个层面上。

    OpenHuman 的记忆是"立体"的——你能从全局看全貌，也能沿着某个实体一路钻到原始对话。

   

   Bucket-Seal 机制：自动压缩的引擎

   三层树是怎么"自动整理"的呢？

   它有一个叫 Bucket-Seal 的机制。

   翻译成中文是：桶 + 封印，也基本就是它的工作原理：

   
    新数据进来后，先扔进 L0 缓冲区（桶）

    当桶满了——具体来说是累计达到 50,000 tokens，或者积累了 10 条数据——触发"封印"

    封印时，把桶里所有内容交给 LLM，生成一份摘要（SummaryNode）

    这份摘要自动升入 L1 层

    当 L1 层也积累了 10 个同级摘要，再触发一次封印，升入 L2……

    如此级联向上，每一层都是一次"压缩"

   

   啥用呢？

   假设你把飞书连上作为信息源了（它还不支持……）：

   你 3 个月前在飞书跟同事讨论了一堆信息，它们进入记忆系统后，会被自动压缩成一段精炼的摘要，挂在那棵源树的 L1 或 L2 节点上。

   当你的 AI 需要"回忆"那次讨论，它可以从全局树的月度摘要→周度摘要→源树的 L1 摘要，一路精确导航到原始对话。

   不是全量搜索，是层级导航。或者叫“渐进式披露记忆”。

   
    💡 产品洞察：

    Bucket-Seal 的精髓在于它的惰性——不主动干活，满了才压缩。这保证了两个重要特性：

    
     低成本：热路径（数据进来时）没有 LLM 调用，只有廉价的启发式评分

     不丢信息：压缩发生在后台，原始数据始终保留在磁盘上

    

   

   04 / 数据是从哪来的？

   记忆树的"原料"从哪来？这是 OpenHuman 另一个值得拆解的设计。

   Composio：118+ 服务的一键接入

   OpenHuman 底层用了 Composio[1] 作为数据接入层，提供 118+ 第三方服务的 OAuth 一键接入。

   已原生支持自动摄取的服务包括：

   
    
     
      
       类型
       服务
       说明
      

     
     
      
       💬 Chat
       Slack / Discord / Telegram / WhatsApp
       消息自动同步
      

      
       📧 Email
       Gmail / 通用 IMAP
       邮件自动拉取
      

      
       📄 Document
       Notion / Google Drive / 会议记录
       文档自动入库
      

      
       🔧 Dev
       GitHub / GitLab
       代码和 Issue 追踪
      

      
       📊 Social
       Reddit / Instagram / Facebook
       社交媒体监控
      

     
    

   
   关键机制：Auto-fetch。

   每个接入的服务，每隔 20 分钟自动同步一次新数据。

   不需要你手动触发——连上 Gmail，它就开始帮你"记"每一封新邮件。

   从原始数据到标准化格式

   不管数据从哪来，最终都要经过一个标准化器（Canonicalizer），变成统一的 Markdown 格式：

   
    聊天记录：## 2026-05-19T14:30:00Z — 张三\n消息内容

    邮件：From: 张三 | Subject: 项目进展 | Date: ...\n正文内容

    文档：直接裁剪为 Markdown body

   

   标准化后，进入分块器，切成 ≤3000 tokens 的小块，每块生成一个确定性 ID（基于内容的 SHA-256 哈希）。

   
    
   
   05 / 它不只是"记住"——还有"想"

   OpenHuman 记忆系统还有一个有意思的设计：它有一个"潜意识"模块。

   Subconscious：后台一直在想

   大多数 AI 助理是"你问我答"的模式——你不说话，它就安静地等着。

   OpenHuman 不是。

   它有一个后台循环，每 5 分钟跑一次"tick"（心跳）。每次 tick：

   
    构建态势报告：从记忆树中拉取最新变化——哪些实体热度在涨？哪些新摘要刚生成？最近有什么反思？

    评估任务：检查有没有待办事项该做了

    生成反思：发现跨来源的模式、异常、机会

   

   反思的六种类型：

   
    
     
      
       类型
       含义
       示例
      

     
     
      
       🔥 热度突变
       某个实体被高频提到了
       "张三在 Slack/邮件/Notion 都出现了"
      

      
       🔗 跨源模式
       多个来源指向同一件事
       "Gmail 和 Slack 都在讨论同一个客户问题"
      

      
       📅 每日摘要
       新的全局回顾生成了
       "今天的重要事件汇总"
      

      
       ⏰ 截止提醒
       引用了近截止日期的摘要
       "项目 X 的 deadline 是明天"
      

      
       ⚠️ 风险模式
       发现潜在风险
       "连续 3 天没人回复那封关键邮件"
      

      
       💡 机会模式
       发现潜在机会
       "竞品刚发布新功能，你的产品有对应优势"
      

     
    

   
   安全边界：观察但不行动

   这些反思不会自动执行任何操作——它们只出现在 Intelligence Tab 里，等你来看。

   如果 AI 判断需要执行写操作（发邮件、创建文档等），会创建一个 escalation（升级请求），需要你手动批准。

   
    💡 产品洞察：

    这背后的理念是——AI 应该是一个"观察者"而不是"行动者"。它负责发现、整理、提醒，但把决策权留给你。这比那些"全自动"的 Agent 设计要克制得多，也安全得多。

   

   06 / Obsidian Wiki：你信任你的 AI 的记忆吗？

   这是 OpenHuman 记忆系统最有"品味"的一个设计决策：

   所有记忆，字面上就是你电脑上的 Markdown 文件。

   你可以用 Obsidian 打开这个文件夹，看到 AI 的每一个"记忆"：

   
    每条原始对话、每封邮件、每篇文档，都是一个 .md 文件

    每个层级摘要，也是一个 .md 文件，通过 [[wikilink]] 链接到它的子节点

    自动标签（person/张三、project/Phoenix）让 Obsidian 的图谱视图直接变成知识网络

   

   他们引用了一句话：

   
    "You can't trust a memory you can't read."

    你无法信任一个你看不到的记忆。

   

   这句话直接引用了 Karpathy 的 Obsidian Wiki 工作流——一个你生命中每件有趣的事都变成可链接笔记的个人知识库。

   这意味着：

   
    透明性：AI 记错了东西，你直接找到那个文件，改掉它

    可迁移性：不用 OpenHuman 了？你带走一个完整的个人 Wiki

    可审计性：你随时可以审查 AI 到底"记住"了你的哪些信息

   

   
    
   
   07 / 技术细节：它"不吃"LLM 的算力

   记忆系统的运行成本是做产品时必须考虑的。

   OpenHuman 有几招控制成本的设计：

   
    
     
      
       设计
       作用
       效果
      

     
     
      
       热路径无 LLM
       数据进来时只做启发式评分
       摄入零 LLM 成本
      

      
       TokenJuice 压缩
       工具调用结果进入 LLM 前压缩 80%
       6 个月邮件同步成本个位数美元
      

      
       惰性主题树
       不热的实体不建树
       避免为冷门信息浪费资源
      

      
       软回退机制
       LLM 摘要失败时用简单拼接替代
       管道永不中断
      

      
       本地模型优先
       简单任务用本地 Ollama
       免费评估
      

     
    

   
   
    💡 产品洞察：

    这里有一个很重要的产品原则——确定性优先于概率性。

    热路径上没有 LLM 调用，意味着你的记忆系统不会因为 API 限流、模型故障而停摆。LLM 只在后台"深度整理"时才登场。

   

   08 / 它"不够好"的地方

   好归好，但对国人不友好。

   OpenHuman 目前支持的信息源渠道：

   Slack、Gmail、Notion、Google Drive、GitHub、Discord、Reddit、Instagram、Facebook、WhatsApp……

   全是海外 App。

   对于中国的个人用户和产品经理来说，我们日常用的是什么？

   
    微信 / 飞书 / 钉钉（聊天）

    微信读书 / 得到（知识）

    石墨文档 / 飞书文档 / 语雀（协作）

    小红书 / 即刻 / 知识星球（社区）

    本地的 Word / PDF / Markdown 文件（工作资料）

   

   OpenHuman 的记忆系统做得再好，如果我的数据源喂不进来，就等于没有记忆。

   好在它是开源的。并且它的记忆树架构和数据源是解耦的。

   标准化器（Canonicalizer）把任意数据源转成统一 Markdown，然后才进入记忆树。这意味着——

   只要我们能把任何格式的文档（Word、PDF、Markdown、JSON、纯文本）标准化成 Markdown，就能复用整套记忆树的逻辑。

   这正是我们需要做的。

   09 / 一个解决思路

   基于 OpenHuman 记忆系统的核心逻辑，我设计了一个 Skill（技能）。

   它能做什么：

   
    指定任意本地文件夹，Agent 自动扫描并识别所有文档（Word、PDF、Markdown、JSON、纯文本）

    根据文档规模制定处理计划，半夜自动激活来干活，干完输出交接文档

    统一转成 Markdown，按照 OpenHuman 的记忆系统逻辑进行记忆抽取

    输出为 Obsidian Wiki——带标签、带层级、带 wikilink 的完整知识库

   

   你只需要把你电脑上的文件夹路径告诉它。

   这个 Skill 的 1.0 版本我放在 AI 学习行动圈知识星球里了，后续我会持续迭代它的稳定性，感兴趣可以在星球搜索「记忆树」下载体验。
