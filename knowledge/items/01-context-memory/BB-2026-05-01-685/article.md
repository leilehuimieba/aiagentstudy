   On-Policy Distillation（OPD）正在成为大模型后训练的标准组件。和传统 SFT 只在 teacher 生成的轨迹上训练不同，OPD 让 student 自己 rollout，再由 teacher 在 student 实际访问到的状态上提供 token-level feedback——既缓解 exposure bias，又提供比 outcome reward 更密集的学习信号。Qwen3、MiMo-V2、GLM-5、DeepSeek-V4 的 post-training pipeline 里都已经采用了 OPD。

   OPD 的原始形式需要在每个 token 位置上计算整个词表的 KL 散度，计算开销很大。因此，现在主流的做法是只在 student 采样到的 token 上计算 teacher-student log-probability ratio 作为 reward，这是对 reverse-KL 目标的无偏单样本蒙特卡洛估计，避免了词表维度的计算。这就是 sampled-token OPD，也是本文所说的 vanilla OPD。

   但我们在实践中发现，vanilla OPD 有严重的训练病理：accuracy 前几百步先跌后涨，response length 大幅震荡，最终效果还比 full-vocab OPD 差了 8 个点以上。

   为什么？问题出在这个 token-level reward 上：

   
    
     
      
       
        
         
        
        
         
        
       
       
        
       
       
        
       
       
        
       
       
        
         
        
        
         
        
       
       
        
       
       
        
         
        
        
         
        
       
       
        
         
        
       
       
        
         
        
        
         
        
       
       
        
       
       
        
       
       
        
       
       
        
       
       
        
         
        
        
         
        
       
       
        
       
       
        
         
        
        
         
        
       
       
        
         
        
       
       
        
         
        
        
         
        
       
       
        
       
      
     
    
   

   这个 log-ratio 无界——当 teacher 或 student 对某个 token 的概率接近 0 时，reward 可以爆到 -50 甚至更极端。

   在 full-vocab OPD 里，这些极端值会被整个词表上的概率加权期望平均掉；但在 sampled-token OPD 里，student 采到哪个 token，梯度就直接吃到那个 token 的 reward，极端 log-ratio 会毫无缓冲地变成高方差梯度。

   面对这个不稳定，常见的做法是加 clip、tanh、z-score 做 reward 后处理。但我们的实验表明，这些方法都没有真正解决问题。

   原因在于，它们都保留了 log-ratio 作为底层 reward，只是在 log 已经把低概率差异放大成极端数值之后再做压缩或归一化——clip 和 tanh 压缩得太晚，z-score 甚至可能翻转 reward 符号。

   换句话说，只要 log 还在，从概率到 reward 的映射就是无界的，后面怎么补救都是在处理后果。

   既然所有保留 log 的修补都失败了，结论很自然：要换掉的不是后处理，而是 log 本身。我们提出 PowerOPD：用 Box-Cox 幂变换替换 log，得到一族天然有界（ 
     
      
       
        
         
        
        
         
        
        
         
        
        
         
        
        
         
        
        
         
        
        
         
        
       
      
      
    ）、符号一致的 reward—— 
     
      
       
        
         
          
         
         
          
         
         
          
         
        
        
         
        
        
         
          
         
         
          
         
         
          
         
        
        
         
        
        
         
          
         
         
          
         
         
          
         
        
       
      
      
    。

   它不仅修复了训练不稳定，还超过了 full-vocab OPD，同时省了 59.2% 的训练时间和 23.1% 的 GPU 显存。单个 benchmark 上最高提升 +16.75 Avg@8 / +15.00 Pass@8。

   Vanilla OPD 到底有多不稳？

   在讨论reward设计之前，先看一组训练曲线，直观感受vanilla OPD的问题。

   在 Qwen3-4B teacher→Qwen3-1.7B student的MATH-500 设置下，vanilla OPD有三个典型症状。

   结果：全都不能真正解决问题（回看图 2）。

   clip 和 tanh 的问题是时序上的——它们在 log-ratio 已经把低概率差异放大成极端数值之后才出手。哪些 token 被 log 变成"高杠杆 token"这件事已经发生了，后面再压缩只是在补救后果。

   z-score 的问题更严重：batch 标准化会改变 reward 符号。但在 OPD 里，reward 符号就是学习方向——teacher 概率更高应该是正 reward，student 概率更高应该是负 reward。一旦符号翻转，不是尺度问题，而是直接把学习方向搞反了。

   
    问题不在后处理不够，而在 log 本身。真正需要改的，是从概率到 reward 的映射函数。

   

   诊断清楚了，药方也就清楚了

   三个病理都指向同一个根因：log从第一步就不该出现在reward里。我们需要的不是log之后的后处理，而是在概率→reward的映射层面，直接把log换掉。

   一个合理的OPD reward至少要满足两条性质：

   P1：有界性。 reward不能无界，否则rare sampled token会产生 catastrophic gradient update。

   P2：符号一致性。 teacher概率更高→正reward，student概率更高→负reward，相等→零。

   vanilla OPD的log-ratio满足P2（log单调递增），但不满足P1（log在0附近发散）。

     和  
     
      
       
        
         
        
        
         
        
        
         
        
        
         
        
        
         
        
        
         
        
        
         
        
       
      
      
    ，ratio都是20，log给一样大的reward。但前者teacher和student都觉得这个token几乎不可能，只是在极低概率区域有个噪声差异；后者teacher真的认为这个token plausible。

   PowerOPD则把reward幅度和绝对概率挂钩：

   
    
     
      
       
        
       
       
        
         
        
        
         
        
        
         
        
       
       
        
         
        
       
       
        
       
       
        
         
        
       
       
        
         
        
        
         
        
       
       
        
       
       
        
         
        
        
         
        
       
       
        
         
        
       
       
        
       
       
        
       
       其幅度由
       
        
       
       
        
       
       
        
       
       
        
       
       
        
       
       
        
       
       
        
         
        
        
         
        
       
       
        
       
       主导。
      
     
    
   

    
     
      
       
        
         
        
       
      
      
    越大，"高概率"的门槛越高。 
     
      
       
        
         
        
        
         
        
        
         
        
       
      
      
     时 
     
      
       
        
         
        
       
      
      
    算高概率， 
     
      
       
        
         
        
        
         
        
        
         
        
       
      
      
     时 
     
      
       
        
         
          
         
         
          
           
          
         
        
        
         
        
        
         
        
       
      
      
    ，已经快被过滤掉了。

   所以 
     
      
       
        
         
        
       
      
      
    是一个"概率区域选择器"：

   
    
     • 小 
       
        
         
          
           
          
         
        
        
      ：保留更宽的 token-level 信号

    

    
     • 大 
       
        
         
          
           
          
         
        
        
      ：过滤低概率噪声，聚焦高支撑 token

    

    
     • 极限 
       
        
         
          
           
          
          
           
          
          
           
          
         
        
        
      ：退化回log-ratio，重新暴露无界问题

    

   

   这也解释了实验中一个非常稳定的趋势：更大的 
      
       
        
         
          
         
        
       
       
     通常带来更高 accuracy、更短 response、更稳训练。

   实验：PowerOPD 不只是更稳，还更强

   在四组Qwen3 teacher-student设置（0.6B和1.7B student×4B 和 8B teacher）和六个数学推理 benchmark 上做了全面评估。

   第一个结论：PowerOPD 大幅超越 vanilla OPD

   跨四组设置的平均提升是 +4.47 Avg@8/+4.06 Pass@8。最大 benchmark-averaged gain 出现在 Qwen3-4B → Qwen3-0.6B 设置：Avg@8 从19.13提升到 25.50（+6.37），Pass@8 从 36.18 提升到41.89（+5.71）。单个benchmark上，最大提升达到 +16.75 Avg@8（AMC23）和 +15.00 Pass@8（AMC23）。

   第二个结论：超越所有 post-hoc 修补

   最大 benchmark-averaged gain 是 +3.01 Avg@8/+3.54 Pass@8。z-score 甚至在部分设置下比 vanilla OPD 还差，和我们的诊断一致——符号翻转比不修更糟。

   第三个结论——这个最反直觉

   Sampled-token 方法在传统认知里就是 "便宜但有方差的近似"——比 full-vocab 省计算，但效果一定更差。

   
    但 PowerOPD 说明恰好相反。sampled-token+bounded reward，不仅比full-vocab OPD更快（省 59.2% wall-clock time、23.1%GPU memory），效果还更好：最大提升 +2.59Avg@8/+8.90 Pass@8。

   

   这说明 sampled-token OPD 的瓶颈从来不是 "sampled" 本身，而是 reward shaping 没做好。当 reward 从无界 log-ratio 换成有界 power reward 后，sampled-token OPD反而变成了更高效也更强的训练目标。

   Takeaway

   OPD 训练不稳定，不是on-policy本身的问题，也不是RL技巧没调好。

   
    真正的问题是：vanilla OPD把无界 log-ratio直接当reward，于是低概率区域的偶然差异被放大成极端梯度。PowerOPD 的解法很干净——把log换成 bounded power reward，用一个指数  
      
       
        
         
          
         
        
       
       
     控制reward聚焦的概率区域。一行公式，drop-in替换，不改rollout、不改teacher scoring、不改policy-gradient框架。

   

   最终效果：更稳（梯度 3000×↓）、更强（Avg@8/Pass@8 显著提升）、更省（59.2%time↓、23.1%memory↓）。
