内容概要

本次演讲中，Kitze 幽默地分享了他从 10 岁起对生产力工具的执念，以及试图开发一款“大一统”人生管理应用 Benji 的漫长历程。随着大语言模型的爆发，他意识到传统应用程序的终结已经到来。他详细探讨了目前使用 Discord 等平台管理个人智能体（Agent）的痛点，展示了他自主研发的专属多智能体编排工具 Wolffer。最后，Kitze 预言了人机交互模式的终极反转——未来我们将把 99% 的任务委托给系统级人工智能，由 AI 倒逼人类做出决策，而绝大多数日常消费级应用将从大众视野中消失。

早期对生产力工具的探索与挣扎

[现场调整幻灯片] 哇，后排的朋友，那些不是我的幻灯片。好了，出来了。大家好，我是 Kitze，我们可能在 X 平台上争论过，我的账号是 D。今天是我 34 岁生日，我决定在生日这天来做场演讲，因为管他呢。

[现场笑声] 谢谢大家。我想折磨一下自己，问问在座的有没有 Tinkerer Club 的成员？后排那位正在睡觉的朋友可能会想，他刚才问了什么。好吧，我最近创建了这个极客俱乐部，这是一个非常棒的社区。里面每个人都像是复制粘贴出来的同类人，看着非常有趣，如果你们感兴趣也可以加入。

今天我要谈论的是生产力工具与个人智能体的过去、现在和未来。这一切要从我 10 岁时使用的第一个待办事项应用说起，这听起来有点疯狂。我找到了一本旧笔记本，上面有一些勉强能看清的涂鸦，写着「我今天需要喝果汁」之类的话。我不知道一个 10 岁的孩子为什么需要待办事项清单，但它确实带有复选框。从那时起，我就一直在努力解决生产力的问题。在座的各位，有没有人也跟我一样，永远对市面上的待办事项应用感到不满？因为根本就没有完美的选择。谢谢，谢谢你们的认同，看来不只是我一个人这么想。

大概在 15 年前，我对 Todoist 和其他同类应用感到极度厌烦。于是我开始使用纯文本文件，这远早于现在流行的本地 Markdown 等概念。我使用了一款名为 Tasker 的 Android 应用来管理所有这些文本文件。我可以设置情境提醒，比如连接到 Wi-Fi 时提醒我某事，或者到达某个目的地、骑自行车时收到提醒等等。

所以我一直在试图打造一套生产力系统。我以前有一个 Google Home 音箱，它当时支持把语音命令一分为二。当你说告诉我助手去执行某事时，它可以提取后半句并发送给任何 IFTTT 服务，这非常酷。每当我在家里有需要做的事情时，我只需告诉谷歌语音助手，它就会把任务存下来。它并不聪明，也不是人工智能，但我当时正朝着某个方向努力：建立一个可以让我卸下大脑负担，并以特定方式处理想法的系统。我意识到，我真正想要的从来都不是一个待办事项应用，而是一个类似人生操作系统（Life OS）的东西。

试图开发大一统应用：从 Toodo 到 Benji

所以我慢慢地朝着那个方向前进。2017 年，我做了一个叫 Toodo 的东西。我不太擅长起名字，所以请忽略我做过的所有东西的名字。它就像一个待办事项应用，但所有的任务都会基于优先级系统自动置顶。如果你给任务打上「健康」或「危机」之类的标签，它们就会累积相应的分数并冲到列表的最上方。这在某种程度上帮助我排定了事情的优先级。当然，后来我的 ADHD 症状发作了，我就把那个应用抛到脑后了。

接着我开始做另一个叫 Better 的项目。这个应用的名字很难做 SEO 优化，因为你很难为一个叫 Better 的应用做搜索排名，所以最终我不得不给它改名。但在这一版里，我进行了扩展，加入了习惯追踪、计划表、日程事件等一堆其他功能。因为我意识到，如果不把这些功能整合在一起，我永远无法打造出一个迷你的操作系统。

然后当然是 ADHD 再次发作，我又换用了一堆其他应用。到了 2022 年，我开始制作 Benji。它是以我的狗命名的，我的狗也是它的吉祥物。我的初衷是想要一个能统治一切的应用程序，虽然我可能走得有点极端了。你们可能会想，接下来他大概又加了什么日常习惯、日历事件之类的功能。其实这体现了我有多讨厌做营销。如果你在想：我怎么从来没听说过 Benji？原因在于，每当我想要去做营销、想要把它推广给大众时，我都会想，要不再加一个功能吧，再多加一个功能。

这就导致差不多三四年过去了，我仍然没有把它彻底开发完。但我实在是对现有的状况感到沮丧：用网页应用做这件事，用 iOS 应用做那件事；这个应用支持 Android，那个又不支持；有些是订阅制，有些又需要一次性付费。所以我只想把所有这些功能都揉捏进一个工具里，希望能借此把我的生活拉回正轨。它做到这一点了吗？绝对没有，但我们正在朝这个方向努力。我的愿景是，有朝一日能做出一部 Benji 手机和一个 Benji OS。

有趣的是，我曾在播客里提到过这个想法，那个主持人说：「对于一个连产品落地页都还没有的人来说，这目标可是够宏大的。」确实，我连落地页都没有，但我坚信总有一天我要做出一台 Benji 手机。

其实，无论是用 Notion 还是 Benji 这样的工具来构建这种人生操作系统，最让人头疼的摩擦力在于：你必须通过表单来输入数据。所以我常常在两种状态之间摇摆：要么在整整一个月里，我每天登录 Benji 记录所有事情，严格执行所有计划；要么我就完全无视它，不再关心待办事项或者营养摄入之类的东西，心里只想着不想看它。几个月后，我又会重新回到这个循环，因为使用所有这些工具的过程本身，就存在着巨大的操作摩擦力。

大模型时代的降临与思维转变

后来我们迎来了 ChatGPT 诞生的历史时刻，那感觉太棒了。当 ChatGPT 插件发布时——我不知道你们还记不记得那个远古遗物，它现在已经演变成了 MCP 之类的东西——我立刻给我妻子打了个电话。我说：「亲爱的，一切都结束了。所有的应用程序、所有的 SaaS 都玩完了。GPT 将会吞噬世界，未来一切都会属于 ChatGPT，一切都将在这个系统内完成。Benji 变得毫无意义了，我浪费了好几年的时间。」三年后，她接到了太多次这样的电话，以至于现在完全无视我了。当我惊呼发布了新的 Opus 模型时，她只会敷衍地说挺好的。

其实很多时候并没有发生翻天覆地的变化，但我们确实在朝那个方向前进。在 2023 年，在模型能够原生返回 JSON 格式之前，你得威逼利诱它们才能得到 JSON。我不知道还有谁记得那段日子。你必须在提示词里恳求它：「拜托不要输出任何 Markdown。」然后它会回答：「没问题，这是一些 JSON。」你只能绝望地拒绝。所以你必须去手动解析它、裁剪它，把它强行塑造成 JSON 的格式。

后来我在 Benji 里增加了一个功能，你可以按下一个键盘快捷键启动麦克风录音，当我说话时，它会定期截断我说的内容，然后调用系统接口。当时还没有 MCP 这种东西，它就是直接调用 Benji 的 API。你可以实时看着你的日历事件在移动，待办事项在自动更新。推特上的网友看到后都惊呆了，他们留言说：「天呐兄弟，你应该继续做下去，把它做成个大项目。」但我那该死的 ADHD 又犯了，我的反应是：既然大家喜欢它，它也走红了，那这意味着我们再也不用碰这个项目了。所以那个 Benji 智能助手至今都没有发布，我也完全没有再推进它。

与此同时，有些开发者只拿走了 Benji 中的一个功能——比如食物追踪功能，就是用手机拍张照然后分析卡路里——靠着这一个功能他们赚了几百万。而我的应用里有 60 个未发布的功能。这里面确实有一个深刻的教训。

陷入开源智能体狂热与本地化部署

去年十月，我突然意识到，我正在使用 Claude Code，我完全可以把它用在更多的地方，因为它支持工具调用以及一堆其他特性。也许我能让它帮我报税（希望不会因此进监狱），或者让它帮我整理邮件、安排待办事项等等。

所以当「技能（Skills）」功能推出时，我开始把各种个人技能加载到我的 Claude Code 里。但我很快发现，我现在既有编程技能，又有个人生活技能，模型开始变得混乱了。于是我开始到处问人：我该如何把这个东西变成一个真正的助手？一个运行在 Claude Code 之上，但同时拥有除编程外其他生活工具的助手。但我的 ADHD 再次跳出来说，不如我们把这事儿忘了吧，让 Pete 他们去搞定 CloudBot 这些东西，你根本不需要操心。而且对我来说，Claude Code 的外壳并不合适，因为它完全是基于终端命令行的，而我渴望的是另一种交互方式。

所以当时 Pete 开发出 CloudBot 并在推特上发布时，我的反应是：你居然能通过 WhatsApp 或 Telegram 跟它聊天！对我而言，这就是那个决定性的时刻。这正是我需要的，它能让我的云端智能体配置真正进化到下一个阶段，我的大脑瞬间被点燃了。

我觉得我们当时像是陷入了集体疯狂，整个社区变得像个狂热的教派，每个人都在穿龙虾套装。那段时间真的很疯狂。我加入了他们的 Discord 频道，当时成功配置好 CloudBot 的人还不到一百个。连 Pete 都好奇地问我：「你是怎么弄好的？我们连个新手引导都没有啊！」我给他的回答，跟我现在告诉大家的完全一样：我根本不知道这套配置的底层原理是什么，我就是直接让 CodeX 或 Claude Code 去修复它、修改它，或者去优化内存、执行各种任务。别人会问我 JSON 配置文件里写了什么，我的回答是：「我这四年都没亲自看过 JSON 文件了。」我不知道，我只是让我的机器人去处理，它自己就能把问题修好。

所以在很长一段时间里，我进入了完全的龙虾模式。这是我在维也纳第一次线下聚会时穿着龙虾装的照片。实际上，OpenClaw 的那个 Logo 也是我半夜两点多做出来的。我开始穿戴各种龙虾周边，录制教程，上播客做嘉宾，大谈特谈各种应用场景。最后真正吸引我的是，作为一个从 10 岁起就痴迷于待办事项和生产力的人，我感觉未来终于触手可及了。无论是放在 Google Drive 和 iCloud 里的文件，还是我的演示文稿、高中的老照片，以及我堆积如山未完成的商业想法，我似乎能看到 OpenClaw 如何奇迹般地挥舞着它的钳子，把我生活中的一切琐事都安排得明明白白。

于是我立刻抛弃了所有基于云端的大模型。我进入了一种彻底的极客模式：不再使用 Gemini，不再使用 ChatGPT，也不再依赖云端。我渴望彻底掌握控制权，真正拥有我的个人助手，拥有所有的文件和记忆数据库，甚至可以随时随地删除聊天会话。一切感觉都是完全私有化的。因此，我自然而然地开始为智能体准备我所有的数据。我从一个重度依赖云服务的人，变成了一个极其繁琐的自托管狂魔。一切都必须从云端撤下，必须放在我本地的 NAS 或我自己的电脑上，只有这样我的智能体才能真正地处理这些数据。

当然，这些目前都还是进行中的项目——那种经典的「总有一天我会做完」的项目。但我已经开始向本地托管迁移，比如使用 Nextcloud，将所有内容转为本地的 Markdown 格式。对于任何需要大量 API 调用或 MCP 协议的事情，我宁愿让它们都在本地运行。我已经走到了如此极致的地步。

而且我还重新用回了 Android 手机。我感觉自己某种程度上被这件事彻底迷住了。因为我希望我的智能体能够读取并清理我的手机通知，能够自动安装或卸载应用。在 Android 手机上，智能体几乎可以为所欲为；而在 iOS 上，如果蒂姆·库克允许的话，它可能最多也就给你发个推送通知而已。

[现场屏幕闪烁] 抱歉刚刚闪了一下眼睛，我原本准备了大概 10 到 15 张关于具体应用场景的幻灯片。但后来主办方告诉我演讲时间严格限制在 18 分钟。所以我把这些内容放到了 YouTube 和一些播客上，今天就不在这里赘述了。在座的各位日常应用场景可能比我还多。但在 Tinkerer Club 每周的聚会上，当我们讨论 OpenClaw 时，我特别喜欢问大家一个问题：你们平时都有哪些使用场景？但其中有哪些是 Claude Code 或 CodeX 绝对做不到的？结果一旦抛出这个问题，90% 的场景瞬间就被毙掉了，因为大家会意识到其实用 Claude Code 也能勉强搞定。

当前智能体与聊天界面的局限性

所以我也一直在反思：像 OpenClaw 这样打包好的智能体，它的核心价值到底在哪？我认为，跟单一智能体进行一对一对话体验非常糟糕。想象一下，如果你要把生活中的方方面面全部委托出去，你肯定不希望让同一个人工智能装载着你人生所有的背景信息，然后只通过 Telegram 这种单一聊天界面跟你事无巨细地聊所有事。

因此，越来越多的人开始使用 Telegram 的话题组功能，或者开始使用 Discord、Slack 等工具来整理工作流。我很喜欢 OpenClaw 支持的专业化智能体概念，但并没有太多人真正去使用它。因为这需要具备一种模型架构级的思维：你需要配置系统提示词、设定一系列可用的工具和 MCP 协议，还需要分配权限列表。我很喜欢这种被打包好的感觉，比如我可以明确告诉自己：现在我只跟这个专门的智能体聊健身相关的事情。

现在很多人都在讨论「大语言模型精神错乱（LLM Psychosis）」，而我在这方面简直是疯狂到了极点。看这些，全是我创建的机器人。我试图把每个机器人都限制在生活中的特定用途里，有些专门负责工作，有些绝对不能碰我的私人聊天记录。总之，最后我弄出了五个 Discord 服务器。好笑的是，虽然我在这里滔滔不绝地讲着，但请大家记住：我的生活不仅远没有被彻底解决，反而变得前所未有的混乱。我从来没有在交房租、还房贷或者回复客户邮件上迟到过，但这只是表面上的完美。表面之下就是一团具有表演性质的混乱。所以我现在有了五个 Discord 服务器，每个服务器里还有成堆的频道、线程和嵌套结构。

不可避免地，你可以在整个社区里感受到这种变化。一开始报名参加聚会的人数呈爆炸式增长，大家都兴奋地说：「天呐，每周都有语音通话，我们要颠覆世界了！」但现在去参加聚会可能只剩下五个人了。这慢慢变成了一种类似于互助会的组织，每个人都在抱怨：「是啊，我的系统连最基本的定时任务都没跑起来。」说真的，这让人有些沮丧。但我相信我们会触底反弹，我们会弄清楚这其中的原因。

为什么会变成这样？因为对我而言，它在最关键的地方依然不可靠。比如定时任务的执行、多智能体协同、智能体之间的对话等。有时候智能体在下一条消息就直接失忆了，问你：「啊？你在说什么？」而我只能抓狂地回复：「消息就在你上面！你只需要往上看一条就行了！」虽然这些问题每天都在修复和更新，但我至今还没看到它能真正完美运转。这不是 OpenClaw 或任何其他智能体的错，而是因为 Discord 和 Telegram 从一开始就不是为了做人生操作系统而设计的。我们只是强行把它们捏成这种形状罢了。它们永远不会是全面管理生活的正确 UI 界面。我们现在使用它们，更像是在找到真正的替代品之前的一种妥协。

最后，正如我喜欢称呼它们为 Benthropic 一样，这种没有灵魂的大模型破坏了技术的魅力。当你调用大模型跟它对话时，感觉就像在对着一盒麦片说话，它毫无个性可言。你让它尝试做某事，它说好的。你问：「你做完了吗？」它说没有。你质问它：「但我刚才告诉你去做了啊！」它回答好的，我这就去做。你再问：「你做完了吗？」它还是回答没有。最近和 OpenClaw 的每一次对话都像这样，这快把我逼疯了。

打造专属智能体工作流：Wolffer

那么现在该怎么办？我们将何去何从？我看到屏幕上显示还有六分钟。我看到了两种相互博弈的未来，但我认为从长远来看，这两种路线都不会是最终的赢家。一种方向是自定义智能体，比如 OpenClaw、Hermes，或者未来可能出现的其他开源方案。另一种方向是云端智能体，现在每家公司都想在这个领域分一杯羹，都在打造自己的云端协同解决方案。

自定义智能体的路线永远无法普及，因为它们只适合极客玩家。在 Tinkerer Club 里，甚至有成员在自己动手制造弹珠机，极客们喜欢折腾一切。但现在就连他们也受够了为了让系统跑起来而不断调试。更别提那些有自己真实生活的人了，那些忙于工作、生活琐事的人，根本没有时间去微调这些参数。大众想要的是现成的、开箱即用的解决方案。当然，我不一样，如果不是我亲手折腾的，我就永远不会满意。

再来说说云端智能体。我试用过某款云端协同工具大概五分钟，我的反应是，这也太受限了吧！它能做的事情连 OpenClaw 的 5% 都不到。所以，云端方案注定是面向大众的，但它永远无法满足极客群体的需求。所以这两种方向并存。就我个人而言，我会怎么选？目前，我正在 OpenClaw、Hermes 和 Paperclip 之间反复横跳。我还在尝试纯终端复用器配合 CodeX 的方案。很多时候，当我对前三款工具感到极度沮丧时，我会怒骂一句然后打开终端，叹息说也许现在的智能体就是没那么聪明。所以我每天都在这些工具之间来回切换并深度使用。

但我内心的犹豫感非常强烈。比如，我想查一下今天活动场地的位置，我有两个选择：要么直接打开活动网站，要么去 Discord 里问我的智能体。但当时的我想，我一点也不想跟那个燕麦盒子对话。因为它会一直反问你是否准备好让它找地址了，这简直太疯狂了。

所以很自然地，我开始自己动手写工具。这个工具永远不会公开发布，它不是为大众准备的，只是我个人的一个实验。我给它取名叫 Wolffer。我并不是想把它做成大众爆款，只是想尝试怎样才能在 CodeX 或 Claude Code 之上构建一个轻量级的抽象层。我甚至不敢大量调用官方模型代码，生怕一不小心就进去了，所以目前它只跑在 CodeX 上。

它没有任何可扩展性，也不支持成百上千种大模型接口。我先来说说它的缺点：让人抓狂的是，你必须使用这套程序原生的聊天 UI 界面，完全不能用 Telegram 或 iMessage 等外部应用，它不支持任何第三方聊天工具。这一点跟 OpenClaw 和 Hermes 完全相反。它的架构设计也没有考虑插件生态，我的理念是把所有东西都写死在里面。它甚至没有记忆系统，所有的功能都不是开箱即用的，也不怎么模块化。它是由一个患有 ADHD、像松鼠一样跳跃的大脑开发出来的，可能到月底我就彻底把它抛在脑后了。它没有得到风投的注资，也没有一个酷炫的龙虾 Logo。这些都是它的缺点。

但它的优点在于，它的对话是非常可预测的。我做的这套 UI 界面，是专门为了多智能体编排、多话题、多线程对话量身定制的。所有的一切都是为了这个核心目的而生。它不像 Discord，你需要生搬硬套地把它塑造成你想要的样子。我最喜欢的一个特性，源于我根本不相信智能体的记忆力。有人惊呼终于解决了智能体的记忆难题，但我深知他们绝对没有真正解决这个问题。

我坚信的方法是嵌套主题（Nested Topics）。比如我有一个类似工作到项目的树状层级结构，当我处于子话题下聊天时，在第一次的提示词中，系统会自动注入所有父级话题的描述。因此，当我和智能体对话时，它不需要从什么虚无缥缈的记忆库里去检索。它只需要一层层向上读取背景描述，打包在一起，瞬间就能明白我的工作内容并提供正确的支持。相比于指望某个黑盒记忆系统，这种粗暴直接的方法能让我获得更好的效果。

它还支持工作空间，我可以在不同的工作区之间无缝切换。我以前非常讨厌那些看不见工具调用细节的界面，在我的系统里，你能看到系统发起了哪些工具调用，能折叠或展开它们，能看到代表加载状态的旋转图标，还有明确的停止按钮，再也不用去敲繁琐的斜杠命令了。它的定时任务也是完全可预测的，当你收到一条定时任务的消息时，它实际上已经读取了整个对话的上下文，并且会在界面上打上明确标签，所以你不会感到困惑智能体为什么失忆了。

这里还有专门用于管理智能体的 UI 界面。当我在某个话题下聊天时，我可以在屏幕右侧清楚地看到当前接管的智能体名字，它使用的是哪个模型，具备哪些能力。这能极大帮助我明确我当前在和谁说话，如果发现不对劲，我只需轻轻一点去除该能力，它就立刻生效了。

我本来想在幻灯片里放几张截图的，但因为程序部署在我家里的设备上，今天现场没法演示。但请大家自行脑补一下那些非常酷的界面。我很喜欢它内置知识库和文档管理的方式，你可以直接在里面编写 Markdown 文档。你可以随时通过艾特功能引入这些文档，提供极其精准的上下文引用，而在 Discord 里你只能艾特其他人类成员。

预测未来：AI 角色反转与应用程序的消亡

接下来我想谈谈未来的趋势，因为我上面做的这些折腾，绝对不会成为主流趋势。那么，行业接下来会发生什么？我认为，我们目前使用电脑的方式极其荒谬可笑。有人赞同我的观点吗？当你们打开电脑时，有没有一种深刻的感悟——电脑根本不应该是现在这个样子！有一个人举手了，两个……看来有很多人深有同感。

当我离开几小时后重新打开电脑，迎接我的是 17 个我已经很久没用过的应用的更新提示，以及一堆从昨天起就没关掉的浏览器标签页。我所设想的未来是这样的：计算机能够自动摄取关于我生活的所有信息——手机通知、电子邮件、待办事项以及生活发生的一切。然后，它会根据我离开电脑的时间长短，自动推测并向我展示下一个需要处理的任务，接连不断。它甚至能在适当的时候让我休息一下，对我说：「嘿，够了，先停下来，我们现在该做点别的。」

所以在某种程度上，我认为 AI 与人类的角色将会发生反转。目前我们向 AI 下达提示词的交互方式，未来将会完全倒置。真正拥有极致生产力的人，将会把 99% 的事务都委托给 AI，然后由 AI 来向你发出提示。比如，AI 会主动问你：「嘿，你还没把护照照片发给我。」或者问你这件具体事务打算怎么处理。人类的工作将仅仅变成做决策、点击表单或是回答问题。但在后台，总有一个系统在持续不断地为你运作，而不是像现在这样，需要你无休止地去引导它。

有人可能会反驳：「但我奶奶这辈子都不可能去写代码啊。」我完全同意这种观点。因为我认为，按照目前的发展方向，我们未来根本不再需要绝大多数的消费者级应用了。是的，你的奶奶、母亲或朋友，都不需要去敲代码。他们只需坐在这套未来感十足的全新操作系统面前，就能完成任何想做的事情。交互界面会根据任务需求即时生成。他们只会专注于完成任务本身，而会彻底忘记需要下载应用这种旧观念。

当然，极少部分的专业应用程序将会存活下来，但那只属于极少数需要专业软件做电影调色或音乐制作的人士。但对于绝大多数普通人而言，他们只需要对着电脑说话，电脑就会自动执行命令，所有的交互界面都将是实时按需生成的。

我还认为，如果最后是苹果公司在这场竞争中赢麻了，那将是一件极其讽刺且有趣的事情。因为目前的本地大模型变得越来越强大，今年和明年还会迎来巨大的飞跃。对于大多数普通人而言，如果 Siri 这样的本地智能体能获取手机上所有已安装应用的底层工具调用权限，那完全就足够了。他们不需要为 API 额度付费，数据永远不会离开本地设备，而手机就能奇迹般地处理好一切事务。

目前最新的 Google Pixel 手机已经能够在后台自动调起应用、帮你点咖啡以及完成一堆琐碎任务了。所以我深信这就是一切事物的发展方向。我已经超时了，感谢大家听我的长篇大论，希望能有机会在会后和大家继续探讨。非常感谢大家，谢谢。
